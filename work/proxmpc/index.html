Context and Problem

ProxMPC builds on my MyNMPC research. The aim is to make the control engine reusable, connect it to Nav2 and evaluate its behaviour alongside other navigation controllers.

My Contribution

I maintain ProxMPC as an independent open-source project. Its scope includes the controller architecture, ROS 2/Nav2 integration and the simulation benchmark workflow. The repository records the implementation, tests and changes.

Technical Approach

  • Control core: SQP repeatedly constructs quadratic subproblems, solved with ProxQP. Eigen handles linear algebra.
  • Nav2 plugin: connects the core to navigation inputs and command output, with lifecycle and failure handling.
  • Vehicle models: separate model plugins allow unicycle and bicycle dynamics to use the same engine.
  • Obstacle handling: supports costmap-based inputs and predicted obstacle motion. The documentation distinguishes reactive and predictive configurations.

Results and Evidence

The benchmark framework runs repeatable scenarios covering open paths, static obstacles and moving obstacles. It compares ProxMPC with DWB, MPPI, Regulated Pure Pursuit, Graceful and Vector Pursuit, recording tracking, computation time, clearance and collisions.

The published comparisons use a simulated kinematic plant on a specified x86-64 host. Configuration files, execution commands and the comparison report are available in the repository.
